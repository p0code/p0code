# `p0d` RPC, HTTP, and SQLite Porting Inventory

This document maps the entire backend surface of `apps/server` (~308k non-test LOC in `apps/server/src`, plus ~260k LOC in server-consumed `packages/*`) to guide incremental porting to the native Go daemon `apps/p0d` behind the HTTP/WebSocket proxy described in [PLAN.md](./PLAN.md).

## 1. Surface Summary

- **WebSocket RPCs**: **267** `Rpc.make` definitions in `packages/contracts/src/rpc.ts` (**234 unary**, **33 streaming**), 1-to-1 implemented in `apps/server/src/ws.ts` over `/ws` (`effect/rpc`, `RpcSerialization.layerJson`).
- **HTTP / Non-RPC WS Routes**: **79** fixed routes + dynamic bundled plugin routes across `apps/server/src/server.ts`:
  - **54** typed `EnvironmentHttpApi` endpoints across 10 `HttpApiGroup`s (`packages/contracts/src/environmentHttp.ts`).
  - **25** fixed raw `HttpRouter` routes (WebSocket `/ws`, voice WebSocket `/ws/voice`, MCP HTTP `/mcp`, signed asset/upload routes, guest share SSE/CRUD, peer thread SSE/CRUD, preview tunnel & browser stream, device hub proxy, desktop readiness proof, OTLP traces proxy, and static/SPA fallback) plus dynamic bundled plugin `POST` routes.
- **SQLite Tables (`statev2.sqlite`)**: **67** tables created across `apps/server/src/persistence/Migrations/*` (**61 live**, **6 dropped** v1 projection tables), plus `effect_sql_migrations` and the separate lock DB `server-owner.sqlite`.

### Proposed Port Order (Maximizing Early RAM/CPU Savings, Deferring High-Risk Runtimes)

The proxy architecture in `PLAN.md` allows `p0d` to run standalone for idle/non-agent states and only spin up (and idle-reap) the legacy Node sidecar when an unported domain is touched. To reap Node aggressively and cut steady-state RSS from ~300–500 MB down to ~30 MB early:

1. **Phase 1 — Edge, Auth, Settings, Static, Assets & Self-Relay (`p0d` owns the front door)**
   - Domains: Auth/Pairing/MCP OAuth, Settings/Themes/Keybindings/Config, Static/SPA + Asset/Attachment upload/download, Self-Relay tunnel & port proxy.
   - **Why first**: `p0d` must authenticate WebSocket/HTTP connections, serve the UI, and own the public tunnel anyway. Small surface (~12k LOC), zero JS SDK dependencies, eliminates Node for idle/locked/serving states.
2. **Phase 2 — Terminal PTY, Port Scanner, Resource Telemetry, Diagnostics & Storage Cleanup**
   - Domains: `terminal.*` + `subscribeTerminalMetadata`, `preview.stopLocalServer` + `subscribeDiscoveredLocalServers` (PortScanner), `resourceTelemetry`/`diagnostics`/`usage`, `storageCleanup`/`databaseStorage`.
   - **Why second**: **Biggest early RAM/CPU win per line of code.** Moving `node-pty` terminals (4.6k LOC) to Go (`creack/pty` + Windows ConPTY) and moving continuous 1–2s process-tree/port polling (`PortScanner`, `ResourceTelemetry`, `ProcessResourceMonitor`) out of Node eliminates persistent background timers and long-lived PTY buffers that otherwise keep the Node sidecar pinned alive forever.
3. **Phase 3 — Workspace File Indexing/Search & Git/VCS/Review**
   - Domains: `projects.*` (file entries/search/read/write), `workspace.*`, `filesystem.*`, `vcs.*`, `git.*`, `review.*`, `worktreeSetup.*`, `subscribeVcsStatus`/`subscribeVcsBranch`.
   - **Why third**: **Second biggest steady-state RAM/CPU win.** `@ff-labs/fff-node` keeps native file indexes and FS watchers resident in Node memory per project, and `VcsStatusBroadcaster` continuously polls `git status`/auto-fetch across open repos. Go replaces both with low-RSS native goroutines, `git` exec, and `rg`/parallel walk, letting the Node sidecar shut down whenever the user is browsing code/diffs/terminals without running an agent.
4. **Phase 4 — External Forge & Automation Domains (PRs, Issues, Scheduled Tasks, Webhooks, Peer/Guest)**
   - Domains: `sourceControl.*`, `pullRequests.*`, `projectClone.*`, `issues.*`, `issueTrackers.*`, `scheduledTasks.*` + `/api/hooks/*`, `peerLinks.*`, `guestShare.*`.
   - **Why fourth**: Pure HTTP/GraphQL + SQLite + git CLI work with zero Node-only SDKs. Porting scheduled tasks/webhooks ensures background cron jobs and inbound webhooks don't wake Node unless a task actually dispatches a turn to an unported provider.
5. **Phase 5 — Media, Device, Preview Browser & Auxiliary Services**
   - Domains: `device.*` + `/api/device-hub/*`, `preview.*` + `/api/preview*`, Voice/Speech (`/api/voice/*` + `/ws/voice`), `plugins.*`, `sharedMemory.*`.
   - **Why fifth**: Heavy optional RAM consumers (`playwright-core` Chromium + `transcribe-cpp` Whisper models) that are cleanly isolated behind HTTP/RPC boundaries. Can be ported or kept as on-demand sidecars.
6. **Phase 6 — Orchestration V2 Core, Workflows & `/mcp` Server**
   - Domains: `orchestration.*` + `/api/orchestration/*`, `workflows.*`, `/mcp` + `mcpApps.*`.
   - **Why sixth**: The largest tightly coupled core (~125k LOC across `orchestration-v2`, `workflows`, `mcp`, `checkpointing`). Once Orchestration V2's SQLite event store, projection engine, shell/thread streams, and `/mcp` server move to Go, **read-only thread viewing, history paging, search, and MCP coordination never need Node**. Provider turn execution can sit behind a narrow internal `ProviderAdapter` RPC bridge to Node until Phase 7 finishes.
7. **Phase 7 — Provider Runtimes (Incremental, One Driver at a Time)**
   - Port stdio-native providers to Go first:
     1. **Pi** (`pi --mode rpc` NDJSON stdio — 7.8k LOC) and **OpenCode** (`opencode serve` HTTP+SSE — 16.9k LOC).
     2. **ACP family** (Antigravity, Grok, Fx, Kiro, ACP Registry — shared JSON-RPC 2.0 ACP over stdio).
     3. **Muse** (MSP over stdio — replace `@muse-code/sdk` framing).
     4. **Codex** (`codex app-server` JSON-RPC over stdio — large event surface, 9.7k LOC adapter + generated types).
     5. **Claude** and **Cursor** last (tied to JS SDKs — see below).

## 3. Complete WebSocket RPC Inventory (267 Methods)

All 267 methods are declared with `Rpc.make(...)` in `packages/contracts/src/rpc.ts` (using constants from `WS_METHODS` in `packages/contracts/src/rpc.ts:501-767` and `ORCHESTRATION_V2_WS_METHODS` in `packages/contracts/src/orchestrationV2.ts`) and registered 1-to-1 in `apps/server/src/ws.ts` (`ServerWsRpcGroup.of({...})` at `ws.ts:1948`, served by `RpcServer.make` at `ws.ts:3729`). The group is deliberately split into two handler objects (`ws.ts:748-754`) because `RpcGroup.toLayer`'s type cost grows with methods × RPCs and degrades past ~200 methods; Go has no equivalent limit.
