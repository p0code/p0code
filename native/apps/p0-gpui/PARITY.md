# `p0-gpui` parity with the web app

How far the native client (`native/apps/p0-gpui`, talking to `apps/p0d`) is from `apps/web`.
Measured against the code, not plans; update a row when its behavior changes.

- **done**: works against a real `p0d` and was exercised in a running window.
- **partial**: the core path works; what is missing is listed.
- **todo**: not in the native client. Settings sections in this state open the same page of the
  web app served by `p0d` in the browser.

## What cannot reach parity cheaply

- **Browser preview and device streams.** GPUI has no web engine; a native webview loses
  Chromium DevTools and profiles, and server-side streaming adds latency.
- **Office, PDF, KaTeX and Mermaid previews.** No mature pure-Rust renderers; these would open
  externally or need server-rendered images.
- **Rich inline composer chips and screen-reader parity.** Both need sustained custom GPUI and
  AccessKit work rather than assembly of existing widgets.
- **Remote environments.** Needs DPoP keys in the OS keychain, pairing and relay support before
  any remote route is usable.
